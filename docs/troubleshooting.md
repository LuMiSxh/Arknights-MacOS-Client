# Troubleshooting & Diagnostics

This guide helps you locate diagnostic logs, use built-in troubleshooting flags, and resolve common issues with Arknights Client.

---

## Log Locations

All launcher and runtime logs use standard macOS locations or live inside the isolated game directory.

| Log / Diagnostic File     | Path                                                                                   | Contents & Purpose                                                                                                 |
| :------------------------ | :------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| **Launcher Log**          | `~/Library/Logs/com.lumisxh.arknights-client/launcher.log`                             | SwiftUI launcher lifecycle, state transitions, Yostar API checks, download streaming, and prefix migration events. |
| **Previous Launcher Log** | `~/Library/Logs/com.lumisxh.arknights-client/launcher.previous.log`                    | Rotated backup log created automatically when `launcher.log` exceeds 4 MB.                                         |
| **Wine & Game Log**       | `~/Library/Logs/com.lumisxh.arknights-client/wine.log`                                 | Output from the Windows runtime, DXMT, MoltenVK, and game process.                                                 |
| **Unity Engine Log**      | `<WinePrefix>/drive_c/users/crossover/AppData/LocalLow/Yostar/Arknights_EN/Player.log` | Unity's native C# exceptions, asset loading logs, and engine-level diagnostics.                                    |
| **Chromium Log**          | `<GameDir>/Arknights_Data/Plugins/x86_64/VuplexWebViewChromium/log-chromium.txt`       | CEF/Chromium network errors, CEF frame events, and browser warnings.                                               |
| **Chromium Debug Log**    | `<GameDir>/Arknights_Data/Plugins/x86_64/VuplexWebViewChromium/debug.log`              | Fatal Chromium assertions, process crash dumps, or sandbox logs.                                                   |
| **CrashSight Telemetry**  | `<GameDir>/Arknights_Data/Plugins/x86_64/wesight/crashsight_data/`                     | In-game crash telemetry generated by Yostar's CrashSight SDK.                                                      |
| **Installed State JSON**  | `<GameDir>/.arknights-client-state.json`                                               | Recorded manifest hashes and version metadata for the current installation.                                        |
| **Prefix Migration JSON** | `<WinePrefix>/.arknights-runtime-migrations.json`                                      | Records completed Wine, DXMT, and registry migration steps for the prefix.                                         |
| **macOS Crash Reports**   | `~/Library/Logs/DiagnosticReports/`                                                    | Native macOS `.crash` reports if `ArknightsClient`, `wine64`, or Rosetta crashes.                                  |

> **Note:** `<GameDir>` defaults to `~/Library/Application Support/com.lumisxh.arknights-client/Games/Arknights-Global` (or `Arknights-Japan` / `Arknights-Korea`).

To quickly open the log folder from the app:
Open **Settings** (`Cmd + ,`) → **Installation** → **Show Logs**.

## Diagnostic Launch Flags

You can pass command-line arguments to `Arknights Client` when launching from the terminal:

```bash
open "dist/Arknights Client.app" --args --graphics-diagnostics
```

### Useful Flags

- `--graphics-diagnostics`: Temporarily sets `DXMT_LOG_LEVEL=info` and Wine Mac driver channel `+macdrv`. Use this to inspect swapchain creation, backing scale factors, and Direct3D 11 rendering pipeline details in `wine.log`.
- `--no-retina`: Forces Wine to launch in 1x DPI mode regardless of display scaling. Useful if the game window opens with incorrect proportions on custom HiDPI monitors.

### Persistent Defaults

To persistently force 1x rendering without terminal flags:

```bash
defaults write com.lumisxh.arknights-client forceDisableRetina -bool YES
```

To revert back to automatic Retina detection:

```bash
defaults write com.lumisxh.arknights-client forceDisableRetina -bool NO
```

## Common Issues & Solutions

### 1. "Arknights Client is damaged and can’t be opened" (macOS Gatekeeper)

Builds are ad-hoc signed but not notarized by an Apple Developer account.

- **Fix:** Right-click `Arknights Client.app` in Finder and select **Open**, then confirm the launch dialog.
- **Alternative (Terminal):** Remove the quarantine attribute manually:
  ```bash
  xattr -d com.apple.quarantine "/Applications/Arknights Client.app"
  ```

---

### 2. Payment Page Shows "Access Temporarily Restricted" / "Der Zugriff ist vorübergehend eingeschränkt"

If PayPal or credit card checkout displays an error stating _"Something in your browser's behavior made us suspicious"_ or lists your IP address:

- **Cause:** Akamai / PayPal Akamai Bot Protection triggered an IP rate limit after repeated checkout attempts over a short period.
- **Fix:**
  1. Restart your internet router to obtain a fresh dynamic IP address from your ISP.
  2. Connect your Mac to a mobile hotspot.
  3. Wait 1–2 hours for Akamai's temporary rate limit to expire.

---

### 3. Blank or Slow Login / Social Sign-In (Google, Apple, Facebook)

- **Cause:** Social OAuth flows spin up a CEF background process through Wine on first use.
- **Fix:** Allow 5–15 seconds on the first click for the embedded browser to negotiate TLS and initialize in the background. Do not repeatedly click the login button while it initializes.

---

### 4. Game Window Does Not Appear Within 90 Seconds

If the launcher stays on _"Starting..."_ and times out with `runtimeWindowTimeout`:

1. Open `~/Library/Logs/com.lumisxh.arknights-client/wine.log`.
2. Check for Rosetta 2 or Metal errors. Ensure Rosetta 2 is installed on your Mac:
   ```bash
   softwareupdate --install-rosetta --agree-to-license
   ```
3. Reset the Wine prefix migration state via **Settings** → **Installation** → **Repair**, then launch again.

## Reporting Bugs

When reporting an issue on GitHub, please include:

1. Your Mac model and macOS version (e.g., MacBook Air M1, macOS 15.0).
2. The installed game region (Global, Japan, or Korea).
3. Excerpts from `launcher.log` and `wine.log` around the time the issue occurred.

You can use the built-in **"Report a Problem"** button in **Settings** → **Installation**, which automatically opens a pre-filled GitHub issue template with your system specs and recent log tail attached.
